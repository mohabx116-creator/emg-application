## Existing engine integration points

The current implementation provides a safe separation between data projection and workbook writing:

- `BackEnd/src/EMG.WebApi/Modules/ReportBuilder/Services/ReportBuilderService.cs:11-47` obtains authorized projects, calls `IAccountingClassificationService`, preserves imported/current/unresolved dimensions and emits overlap/T/office warnings.
- `BackEnd/src/EMG.WebApi/Modules/ReportBuilder/Services/ReportBuilderService.cs:50-75` groups and projects summary/detail rows. This must remain the calculation source; the XLSX layer must not reimplement classification.
- `FrontEnd/src/Modules/EMG/ReportBuilder/index.tsx:45-54` defines the categories, dimensions and selectable output columns used by the flexible builder.
- `BackEnd/src/EMG.WebApi/Modules/Reports/Services/XlsxBuilder.cs:11-15` is the current export entry point and chooses the embedded project template when available.
- `XlsxBuilder.cs:36-51` already performs fail-closed capacity checks, including the combined building/unclassified finishing capacity.
- `XlsxBuilder.cs:53-135` clones the template package, removes the calculation chain, removes template table formulas and injects exported values. This is the correct foundation for preserving appearance without carrying external links or stale formulas.
- `XlsxBuilder.cs:138-160` preserves fixed template labels and dispatches sheet-specific population logic. Future dynamic export work should extend this dispatch with explicit template families, not force all reports through one shape.

## Dynamic report-to-template selection

| Report Builder selection | Preferred output family | Reason |
|---|---|---|
| One project, original Master Template preset | Consolidated `Sheet1` shell | Exact E:U familiar layout. |
| One project, detail level with operational sections | `191.xlsx`-style detailed workbook | Sections have distinct geometries and trade-specific headers. |
| Multiple projects, consolidated grouping | Consolidated shell with one row per authorized project | E:U is project-oriented. |
| Multiple projects with transaction detail | Consolidated summary plus generated detail worksheets | Do not overload E:U with transactions. Preserve a clear summary/detail split. |
| Custom columns/grouping | Generated worksheet using the closest approved style family | Do not claim exact E:U parity when selected columns have different meaning. |
| Party statement | Supplier/contractor-focused detailed sheet | Use party and dimension columns; do not mislabel it as the Master Template. |

## Dynamic row expansion algorithm

1. Select the template family from report intent, not from the number of rows alone.
2. Read the template's sheet XML before writing and identify merged ranges, table ranges, reserved summary rows, print areas and existing detail rows.
3. Compute capacity from the actual sheet-specific safe region. For concrete, protect summary rows around 30–31. For finishing, treat building and unclassified-finishing rows as one shared capacity where they use one sheet.
4. If the detail count fits, populate values and clone styles from the corresponding template detail row.
5. If safe expansion is approved for that sheet, insert rows before the reserved summary block, copy row height/style/borders/number formats, update table range and print area, then revalidate merges and formulas.
6. If expansion cannot be proven safe, return a structured capacity error. Never return HTTP 200 with omitted records.
7. Remove external links and calculation chains from the generated package. Values must be supplied by the reporting engine, with any diagnostic formulas explicitly generated and tested.
8. Validate the final ZIP/XML package and open it in Excel during acceptance.

## Visual acceptance matrix

### Exact checks

- Worksheet names and order.
- RTL property.
- Consolidated `A1:U31` shell and E:U header order.
- Merged ranges in title/header/summary sections.
- Header fill/font/border/alignment and wrapped text.
- Number formats and typed numeric cells.
- Column widths, row heights, page orientation, print area and print titles.
- Detailed worksheet-specific section labels and summary positions.

### Dynamic checks

- All included records appear exactly once.
- At-capacity and beyond-capacity behavior.
- No overwrite of concrete rows 30–31, steel summary rows, or finishing summary rows.
- No external-link relationships or old calculation chain.
- Unresolved/provenance warnings are visible.
- H/T/office warnings remain visible and are not hidden in totals.
- Authorized project filtering is enforced before export.

### Programmatic and visual test method

1. Compare ZIP/XML structure and key cell style IDs against the verified template.
2. Compare resolved style components: font, fill/theme/tint, border, alignment and number format.
3. Scan formulas and package relationships for external links, stale calculation chains and error tokens.
4. Render every affected sheet in Excel at normal zoom with no cell selected.
5. Review RTL reading order, clipping, merged-cell integrity, print preview, page breaks and summary visibility.
6. Reconcile each exported amount to the Report Builder response and an independent synthetic fixture.
