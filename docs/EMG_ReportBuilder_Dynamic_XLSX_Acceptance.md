# EMG Report Builder dynamic XLSX acceptance

## Result

**PASS for the four synthetic workbooks in Microsoft Excel Professional Plus 2013.** Application integration was verified through backend controller tests, TypeScript, and the frontend production build. The download button was not exercised in a running browser session.

## Integration

`POST /api/reports/builder/export.xlsx` accepts `{ "query": <ReportBuilderQuery>, "presentation": "custom" | "detailed" | "consolidated" }`. The endpoint uses the existing authenticated session, `reports.export` policy, and server-side project scope. The frontend button on `/emg/reports/builder` sends the same query as Preview via the existing Axios client. The presentation selector leaves the query intact. The page displays download progress, success, and errors, including Arabic messages from the endpoint.

Preview and export use the same classification, project, category, party, date, dimension, snapshot, grouping, and sorting rules. Template summaries consume per-project category amounts from that same filtered projection. The transaction sheet follows the selected columns and their order, including provenance when selected. Preview group subtotals keep the chosen grouping. A group that combines dimensions is a subtotal of the selected rows and has no balance interpretation.

## Layout and financial safeguards

- **Detailed** reuses the eleven legacy sheets' styles, theme, tab colors, columns, row heights, merging, RTL, and original table captions. The workbook appends supplier supply and payment sheets when they have records and provides separate preview sheets for the chosen detail level. When both snapshots are selected, the fixed legacy sections show current amounts and the preview sheets retain both snapshots.
- **Consolidated** uses a sanitized layout derived from the audited `شيت مجمع تجريبى.xlsx`. The layout asset has four parts containing geometry, styles, theme, and table headings. The master sheets keep columns E:U in their original order with separate imported and current pages, 24 project rows per page. H stays diagnostic and T stays unapproved. J is contractor workmanship and K is station concrete. R shows office payments and S shows owner funding. Unresolved classifications appear in U and in the selected preview detail and summary. Historical workbook values, cached balances, and external references are excluded from the layout asset.
- **Custom** uses the legacy report styles on the selected preview summary and transaction sections. All layouts have a notes sheet for snapshot overlap and accounting warnings.
- Source strings, including formula-looking values, are emitted as literal Excel text. Table headings use shared strings with whitespace preservation. Financial amounts and dates are typed numeric cells. Numeric precision outside Excel's supported 15 significant digits, oversized text, unavailable layouts, and capacity failures produce structured errors.
- The detailed layout caps detail at 21 excavation, 45 steel, 20 station concrete, 20 contractor workmanship, 42 site, 14 owner funding, and 36 per finishing section. The template table range governs excavation. The new endpoint rejects overflow with HTTP 422 and `XLSX_EXPORT_CAPACITY_EXCEEDED`, including section, count, and capacity. Limits also apply to detailed project count (40), preview summary and transaction rows (30,000 each), and workbook sheet count (512).

The new package tests validate actual XLSX cells, legacy template geometry and styles, table header parity and ranges, and Open XML conformance for Office 2013. They check that formula-looking text stays literal and that implicit numeric cells contain only numeric values. They cover empty results, separate projects and snapshots, explicit unresolved amounts, selected column order, over-capacity rejection, and authorization.

The SQLite controller test combines date, project, category, dimension, and party filters. Two visible supplies are 250 and 125, so the current subtotal is 375 and the historic subtotal is 250. The export equals the independently calculated amounts and the actual preview response. The hidden project and source reference are absent. A user with only `reports.view` fails the actual `reports.export` permission requirement.

The consolidated fixture keeps 120 contractor and 200 station, 30 office payments and 1,000 owner funding. The detailed boundary fixture keeps steel 19 in F51 with 855 in F52, station 13 in H29 with 260 in G31, and contractor 17 in U29 with 340 in U30. A 46th steel row returns the documented 422.

The legacy writer, its tests, the detailed template, and the master template matched their original SHA-256 checks after the work. The backend commands reported existing warnings for obsolete authentication clock APIs and the test SQLite dependency advisory.

### Reproduce the four workbooks

Run from the canonical workspace in PowerShell. Set the output variable to an existing QA directory outside the project.

```powershell
$env:EMG_REPORT_BUILDER_QA = '<local-project-path>'
Remove-Item Env:EMG_P0_TEST_POSTGRES -ErrorAction SilentlyContinue
$emgXlsxBuild = Join-Path $env:TEMP 'EMG-P2A-Dynamic-XLSX-Build'
dotnet test BackEnd/tests/EMG.WebApi.Tests/EMG.WebApi.Tests.csproj --no-restore --filter FullyQualifiedName~ReportBuilderXlsxTests --output $emgXlsxBuild -m:1 -nr:false -p:UseSharedCompilation=false -p:UseAppHost=false
```

## Limits and runtime

Quantities, rates, and balances absent from the reporting projection remain blank in template sheets. Allocation records remain separate in preview, and office fee accrual remains outside the projected cash payments. The export uses typed snapshot amounts, without source spreadsheet formulas or workbook links. Print output and saved edits were outside the read-only Desktop checks.

All four temporary Excel sessions exited. The artifacts remain available for review. The tests used synthetic data or in-memory SQLite. The existing frontend and backend listeners were left running. QA started zero EMG server processes.
